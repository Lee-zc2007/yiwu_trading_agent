# Agent 安全边界

## 可做

Agent 只能调用注册在 `AgentToolRegistry` 的工具：读取外商档案、信用分、最近交易、订单风险、预警列表、客户对比、事件详情和核验清单。每次回复同时返回工具名、参数摘要、数据源 ID 和关联对象 ID。

当前实现通过 `AgentDataGateway` 将 Agent 与 SQLAlchemy 隔离。信用 Tool 只能读取已经保存的评分；如果评分不存在，会返回数据不足，不会触发重算。订单风险 Tool 可经业务网关复用现有规则引擎、异常检测和综合风控服务，但固定使用 `persist_event=false`，不会新增或修改风险事件；调用前还会检查已有评分，避免间接补算信用分。

Tool 层本身只做 Schema 校验、网关转发、输出校验、异常封装和证据引用，不实现交易统计、评分公式、风险规则、异常算法或核验清单生成逻辑。

Conversation Memory 在 Agent 包外通过 `ConversationService` 持久化，并同时校验 `merchant_id` 与 `user_id`。写入前会移除邮箱、电话、地址、敏感编号、长数字和凭证原文；Tool 调用只保存名称、状态及白名单 ID 参数，不保存 Tool 返回数据或可能包含评分、金额的原始摘要。

## 不可做

- 不允许模型直接生成或执行 SQL。
- 不把模型常识当作当前客户事实。
- 不自动修改交易、客户或风险事件。
- 不自动暂停发货、加入黑名单或作最终交易决策。
- 数据不足时必须说明不足，而不是补全不存在的信息。
- 不把完整 Tool 返回值、联系方式、地址、证件/账户编号或 API Key 写入 Conversation Memory。

## LLM 失败策略

只有 `AGENT_MODE=llm` 且存在 API Key 时才请求外部兼容服务。网络错误、无效 JSON、未知工具或工具参数错误都会回退到确定性 Mock Agent；核心风控 API 不依赖 LLM。

## 生产化补充

真实部署需要对提示注入做输入/输出过滤，对外部模型的数据传输取得授权，按字段脱敏，限制速率和预算，记录完整工具调用审计，并对不同角色实施最小权限。
